# RT0 — русскоязычный голос: слепое прослушивание и права

Статус: **только отбор кандидатов на живое испытание**. Аудиофайл,
закрытие LiveKit byte stream, зелёный CI, чекбокс в браузере и отзыв слушателя
НЕ доказывают корректный RTP playout, синхронизацию губ или готовность RT0.

## Один и тот же текст

Все сравнительные голоса должны синтезировать строго:

> Здравствуйте! Рада вас слышать. Давайте спокойно разберёмся, что произошло, и найдём решение.

Источник общего текста: `scripts/rt0_multilingual_voice_audition.py::AUDITION_TEXT`.
В `*.json` каждого результата находится `audition_text_sha256`. Программа
не допускает сравнений, если текста, метаданных или WAV не хватает либо
длительность/формат/контрольная сумма расходятся. Даже эти проверки НЕ
доказывают отсутствие иностранного акцента — это оценивает слушатель.

## Подготовить реальные кандидаты

Применить уже существующий изолированный генератор `scripts/windows_neural_voice_audition.ps1`
для `qwen-design`, `qwen-base` и `chatterbox-v3` только при наличии
допустимого проверенного тестового reference WAV для последних двух движков.
Не путать синтетический MIT-тестовый голос с правом использовать внешний
человеческий голос в коммерческой психотерапии. Один WAV для проверки
работоспособности недостаточен; нужны минимум два кандидата, каждый с
соответствующим `*.json` из генератора **этой версии**.

В PowerShell или CMD из корня точной проверяемой ветки:

```console
py -3.11 scripts/rt0_blind_voice_acceptance.py prepare --source audio-candidates --package voice-review-anonymous --private-manifest voice-review-private/mapping.json
```

Команда создаст `voice-review-anonymous/index.html` и нейтральные
`A.wav`, `B.wav` (до шести). Не выкладывать `mapping.json` вместе с
анонимной подборкой: в нём имена движков и SHA-256 записей. Не перезаписывать
старую сессию сравнения. Сгенерированные записи предназначены для приватного
прослушивания, а не автоматического распространения или коммерческой сборки.

Открыть `index.html` локально, подключить те же наушники и установить одну
и ту же громкость для всех вариантов. Не разглядывать приватную карту до
выставления оценок. Прослушать каждую запись **полностью** и выбрать 1–5 по
пяти критериям: native Russian, pronunciation, prosody, timbre, warmth.
Предоставить сохранённые JSON двух действительно независимых прослушивателей;
дубликат файла или две самооценки одного человека не заменяют независимых
рецензентов. Скрипт не может криптографически установить их личности.

## Документировать права отдельно от качества голоса

Файл `voice-rights.json` должен быть заполнен человеком после просмотра
реальной лицензии **модели, весов, записей и исходного говорящего**, а также
прав на использование в соответствующем коммерческом/терапевтическом
контексте. Начинать со всех `false`; отсутствие подтверждения — отказ.

```json
{
  "schema_version": "rt0-voice-rights-review-1",
  "candidates": {
    "qwen-design": {
      "commercial_use_confirmed": false,
      "therapeutic_context_confirmed": false,
      "voice_reference_consent_confirmed": false,
      "reviewer": "",
      "evidence_url": ""
    },
    "chatterbox-v3": {
      "commercial_use_confirmed": false,
      "therapeutic_context_confirmed": false,
      "voice_reference_consent_confirmed": false,
      "reviewer": "",
      "evidence_url": ""
    }
  }
}
```

Удалять ненужные движки и добавлять присутствующие — перечень должен
совпадать с приватной картой. Для reference-free VoiceDesign поле о правах
голоса всё равно требует осознанного подтверждения допустимого происхождения.
Пример `false` НЕ свидетельствует, что конкретная лицензия запрещает всё:
он означает, что право **пока не проверено**.

После получения настоящих протоколов:

```console
py -3.11 scripts/rt0_blind_voice_acceptance.py assess --package voice-review-anonymous --private-manifest voice-review-private/mapping.json --listener review-owner.json --listener review-independent.json --rights voice-rights.json --report voice-review-private/decision.json
```

`selected_for_live_trial` появляется только если модель получила
средние оценки >=4 **по каждому** критерию, два человека явно засвидетельствовали
прослушивание и независимый ревьюер положительно оформил все обязательные
права. Это **разрешение на тестирование**, а не автоматическое переключение
TTS в production. Никаких текстов пользователя, разговоров, медицинских
данных, API-токенов, частных пользовательских голосов в наборе быть не должно.

## Когда задача действительно закончена

Выбранный голос должен пройти живой маршрут у владельца и независимого
посетителя: первое приветствие, несколько последовательных обменов,
подтверждённое слушателем воспроизведение, честные измерения первой речи,
смену микрофона, STOP во время вывода, обрыв/reconnect и правовую оценку.
Отдельно нужны соответствие внешности персонажа, натуральное ударение,
отсутствие англоязычного/роботизированного акцента и визуально/RTP
подтверждённая синхронизация. Только после этих проверок можно решать о
выборе production TTS и готовности релиза.
