# RT0: выбранные голоса SaluteSpeech (решение 13.10.2026)

**Решение пользователя:** использовать **Александру** для женского персонажа и **Тараса** для мужского персонажа. Это выбранные кандидаты, а не утверждение, что голос уже подключён, аудио воспроизводится или получено право на коммерческое использование.

| Персонаж | Название Сбер | Точный API voice | Частота |
|---|---|---|---|
| Женский | Александра | `Ost_24000` | 24 000 Гц |
| Мужской | Тарас | `Tur_24000` | 24 000 Гц |

Не использовать 8-кГц варианты `Ost_8000` и `Tur_8000` для аватара: они предназначены для телефонии.

**Официальная документация и соответствие кодов:** https://developers.sber.ru/docs/ru/salutespeech/guides/synthesis/voices

**Критический блокер доступа.** Сбер сообщает, что с **15 июля 2026 года** новые подключения к SaluteSpeech API недоступны; пакеты/продление Freemium для физических лиц прекращены. Если у владельца уже есть действующий аккаунт/договор и квота, использовать существующий серверный OAuth-ключ; без него не включать кнопку/профиль как работающий голос и не применять демо-аудио как production TTS.

Источник ограничения: https://developers.sber.ru/docs/ru/salutespeech/api/authentication

## Технический контракт будущего подключения

* Одна каноническая TTS abstraction `TtsPort` и текущие runtime `ActiveTurn`/разрешения; без нового реестра Identity, второго playback owner, browser API secret или параллельной системы маршрутов.
* SaluteSpeech синхронный REST: `POST https://smartspeech.sber.ru/rest/v1/text:synthesize?format=pcm16&voice=Ost_24000` или `Tur_24000`; UTF-8 текст до 4000 символов. Потоковый вариант gRPC `smartspeech.sber.ru` предпочтительнее после проверки реальных задержек.
* OAuth: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, `RqUID` UUID4, Basic authorization key, scope соответствующий существующему проекту. Токен действует 30 минут: получать новый при остатке < 60 секунд. Секреты только серверные; никогда не писать в клиентский JS, логи, evidence или PR.
* 24-кГц моно signed PCM16 LE → существующий защищённый `RealtimeAvatarPcmStream` → Echo D-ID `did.audio-stream`. Сохранить STOP/revoke, ограничение длительности и общего объёма, fail-closed на 401/403/429, не трактовать отправку чанка как подтверждение фактического воспроизведения.
* Автоматическая проверка: оба точных API-кода, отказ при чужом голосе/неправильной частоте/невалидном токене, 4 000-символьный предел, отмена во время стрима, смена женского/мужского голоса без повторного открытия аватара, завершение.
* Живое принятие: реальный русский разговор, первое приветствие, естественная дикция, совпадение пола голоса и аватара, непрерывный звук, A/V, STOP и пользовательское прослушивание. Никакая симуляция CI не заменяет его.

## Важно

Это **выбор двух голосов для реализации**, а не авторизация использования голоса и не разрешение автоматически объявлять релиз готовым. До проверки наличия действующего доступа SaluteSpeech и фактического E2E не переключать production на Сбер. Другие существующие TTS-маршруты сохраняются как резерв, без дублирования решений.
